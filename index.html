rls-guard

📦 Published on npm

An MCP server that points at your own Supabase project and tells you — in plain language — which tables the public anon key can read, then gives you the exact SQL to lock each one down. No dashboards, no sign-up. Your AI assistant runs it for you.

  • Distributed through the AI-recommendation channel. Agents discover and suggest installing it — MCP registries are the new app store for developer tools.
  • Severity that makes sense. Distinguishes accidentally-public tables from intentionally-public content, weighted by what's actually in them.
  • Built from firsthand knowledge. I wrote the Supabase RLS for Prompt Emporium by hand — this tool packages exactly that.

Prompt Emporium

⚙ In development

A personal project I built to learn full-stack development with AI. It's a web app for storing, versioning, and AI-improving prompts and Claude skills — with auth, payments wired up, and a community library. Still evolving; I use it internally and learn from it as I go.

  • First full-stack build. Next.js, Supabase (auth + Postgres + RLS), Stripe, Vercel — all set up from scratch.
  • Learned how to direct AI agents. Built across many Claude Code sessions; figured out how to get consistent, production-quality output.
  • Where I figured out deployment. Vercel deployment config, Supabase environment management, OAuth, webhook handling — most of the hard config lessons came from this project.

About

A little about me

I work in financial services — inside the controls and compliance world that most people read about in quarterly reports. Like a lot of people in that world, I got frustrated watching the gap between what AI could actually do and what everyone was doing with it. So I started building — on my own time, with my own curiosity as the only deadline.

These projects are how I learn. Some are polished, some are rough, all of them taught me something real. That's the honest version of what this site is — a record of the learning, not just the highlights.
